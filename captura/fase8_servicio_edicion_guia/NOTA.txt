REGLA DE NEGOCIO (definida en Fase 3, con 3 aclaraciones nuevas del 29/08)
------------------------------------------------------------------------
Fase 3 dejo dos puntos para esta fase:
- Bloque 6: "guia o linea de TIPO SERVICIO -> se registra e imprime, NO genera
  etiqueta ni toca inventario".
- Bloque 2: "editar guia CERRADA: solo se puede cambiar la CANTIDAD de las
  lineas y el NUMERO DE O.C. Nada mas".

Aclaraciones tomadas con el usuario antes de tocar el esquema (AskUserQuestion):
1. SERVICIO se modela POR LINEA (guia_items.tipo = PRODUCTO / SERVICIO), no por
   guia completa. Permite guias mixtas; una guia 100% de servicios se arma
   marcando todas las lineas como servicio.
2. Al editar la CANTIDAD de una linea que ya movio inventario: se AJUSTA el
   inventario del almacen por la diferencia y se BLOQUEA la edicion si el
   codigo de esa linea ya salio (etiqueta en estado SALIO o REEMPLAZADA).
3. El editor de cantidad + N de O.C. se habilita para CUALQUIER guia (CARGADA y
   CERRADA). En CERRADA queda restringido a esos dos campos; en CARGADA convive
   con la edicion normal de cabecera.

CAMBIOS DE ESQUEMA (migraciones idempotentes en setup.js + database.sql)
----------------------------------------------------------------------
- guia_items + columna `tipo VARCHAR(20) NOT NULL DEFAULT 'PRODUCTO'`
  CHECK con nombre propio (guia_items_tipo_check) IN ('PRODUCTO','SERVICIO').
- guia_items + columna `descripcion VARCHAR(200)` -> texto libre del servicio;
  solo se usa cuando tipo='SERVICIO'. Una linea SERVICIO NO usa el catalogo de
  productos: su producto_id queda NULL.
- guia_items.destino pasa a ser NULLABLE (las lineas SERVICIO lo dejan en NULL)
  y su CHECK con nombre propio (guia_items_destino_check) se recrea admitiendo
  NULL: CHECK (destino IS NULL OR destino IN ('ALMACEN','OFICINA','LABORATORIO','OTRO')).
Ninguna migracion borra datos. Ya aplicadas en sibarita_db local (verificado:
las 19 filas existentes quedaron con tipo='PRODUCTO', 0 con destino NULL,
producto_id sigue nullable).

BACKEND
-------
routes/guias.js
- POST /: cada item admite `tipo`. Una linea SERVICIO se valida solo por
  cantidad (entero > 0) y se inserta con producto_id=NULL,
  descripcion=it.producto_nombre, destino/destino_detalle/recogido=NULL. NO
  genera etiqueta, NO llama a ajustarInventario, NO procesa partidas, NO crea
  ninguna fila en `productos` (fix del code-review: antes un servicio nuevo se
  daba de alta en el catalogo). El resto del flujo PRODUCTO queda igual; el
  INSERT de guia_items PRODUCTO fija tipo='PRODUCTO' explicito.
- GET /:id: el detalle de items trae `gi.tipo`; `producto_nombre` sale de
  COALESCE(p.nombre, gi.descripcion) y el JOIN a productos pasa a LEFT JOIN.
- PUT /:id (reescrito, ahora transaccional):
  * Cabecera: igual que antes (proveedor/numero_oc/direccion/guia_remision/
    factura/estado, campo presente y vacio -> NULL).
  * `items: [{ id, cantidad }]` corrige la cantidad de lineas ya registradas.
    - Bloquea EN_PARTIDA (su cantidad sale del desglose de partidas) -> 400.
    - Bloquea si la linea tiene etiqueta y su estado != EN_ALMACEN -> 409.
    - Bloquea si la etiqueta viva de la linea tiene condicion='USADO' (Fase 5:
      su stock esta en el bucket DEVOLUCION, no NUEVO) -> 409. (fix code-review)
    - Si la linea tiene etiqueta EN_ALMACEN condicion NUEVO: ajusta el
      inventario del almacen por (nueva - vieja) via ajustarInventario (bucket
      NUEVO, mismo delta que el ingreso).
    - Linea que no pertenece a la guia -> 400.
  * Guia CERRADA: rechaza con 400 cualquier campo de cabecera que no sea
    numero_oc o estado (para reabrirla). El resto sigue permitido: numero_oc,
    estado e items.
  * SELECT ... FOR UPDATE sobre la guia y FOR UPDATE OF gi sobre cada linea;
    LEFT JOIN a productos (una linea SERVICIO no tiene producto).
- consulta/productos: agrega `gi.tipo = 'PRODUCTO'` -> las lineas SERVICIO no
  aparecen en la consulta de productos por almacen/guia (no son stock fisico).
routes/dashboard.js
- El "top productos que mas rotan" (GET /api/dashboard/fase2) agrega
  `WHERE gi.tipo = 'PRODUCTO'`.

/CODE-REVIEW (medium, 29/08) - 4 hallazgos, los 4 resueltos
--------------------------------------------------------
1. PUT ajustaba siempre el bucket NUEVO del inventario -> una linea cuya
   etiqueta viva venia de una devolucion USADA (stock en bucket DEVOLUCION)
   quedaba descuadrada. -> se agrega e.condicion al query y se BLOQUEA con 409
   la edicion de cantidad de esas lineas.
2. Las lineas SERVICIO forzaban una fila en `productos` por cada descripcion
   libre. -> guia_items.descripcion + producto_id NULL para SERVICIO; el
   catalogo ya no se ensucia. GET /:id usa LEFT JOIN + COALESCE.
3. Chequeo duplicado muerto de la cantidad SERVICIO dentro de la transaccion.
   -> eliminado (la validacion pre-transaccion ya cubre el caso).
4. Una linea SERVICIO apuntando a un producto EN_PARTIDA se mostraba editable
   pero el backend la rechazaba. -> ya no aplica: una linea SERVICIO no tiene
   producto_id, no puede quedar asociada a un producto EN_PARTIDA.

inicio del test, nunca por patron LIKE sobre numero_guia.
