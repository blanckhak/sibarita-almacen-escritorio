FASE 10 - Modulo nuevo "Compras Diarias" (Bloque 5)
================================================================================
Fecha: 31/08/2026

REGLA DE NEGOCIO
---------------
Bloque 5 del documento del cliente: "Compras diarias: Registrar asociando
Oficina y Solicitud correspondiente." Aclarado en Fase 3 (seccion 20 de
NOTAS_PROYECTO_SIBARITA.txt): MODULO NUEVO APARTE (fecha, oficina, proveedor,
montos), ligado OPCIONALMENTE a una Solicitud de Materiales. No es extension
de otro modulo ni un reporte.

DECISIONES DE ESTA FASE (confirmadas con el usuario antes de construir)
------------------------------------------------------------------
- Estructura: CABECERA (fecha / oficina / proveedor / solicitud opcional /
  observaciones) + N LINEAS con monto (descripcion libre, cantidad,
  monto_unitario). El total = suma de cantidad * monto_unitario, se calcula
  al leer, no se guarda.
- Flujo: SOLO REGISTRO. No hay PENDIENTE/ATENDIDA/RECHAZADA (es un log de
  compras del dia, no un tramite que alguien aprueba). No hay endpoints de
  atender/rechazar ni de edicion/borrado.
- Permisos: lo registran admin + compras. Es el PRIMER permiso de escritura
  del perfil "compras" (antes era solo lectura). Incluye vista de impresion.
- No toca inventario ni etiquetas.

ESQUEMA (migraciones idempotentes en setup.js + database.sql)
----------------------------------------------------------
Solo tablas nuevas, ningun ALTER sobre tablas existentes -> riesgo minimo.
- CREATE SEQUENCE compras_diarias_numero_seq START 1
- compras_diarias (id, numero_compra VARCHAR(20) UNIQUE, fecha DATE NOT NULL,
  oficina VARCHAR(150) NOT NULL, proveedor VARCHAR(150) null,
  solicitud_id -> solicitudes_materiales(id) null, usuario_id -> usuarios(id),
  fecha_registro TIMESTAMP default now(), observaciones TEXT)
- compras_diarias_detalle (id, compra_id -> compras_diarias(id),
  descripcion VARCHAR(200) NOT NULL, cantidad NUMERIC(12,2) NOT NULL,
  monto_unitario NUMERIC(12,2) NOT NULL default 0)
Ya aplicada en sibarita_db local (verificado: las 2 tablas existen, 0 filas,
el resto de la base intacto -> 10 guias, 9 notas, 12 codigos EN_ALMACEN).

BACKEND
-------
backend/src/routes/comprasDiarias.js (NUEVO), registrado en server.js como
/api/compras-diarias:
- GET /            -> lista; filtro opcional ?desde=&hasta= por fecha; trae
  numero_solicitud, usuario_nombre, total_lineas y monto_total (SUM
  cantidad*monto_unitario).
- GET /:id         -> cabecera + numero_solicitud + array detalle.
- POST /           -> soloRoles('admin','compras'), log CREAR_COMPRA_DIARIA.
  Valida: oficina requerida; >=1 linea; cada linea con descripcion,
  cantidad > 0 y monto_unitario >= 0. Si viene solicitud_id, verifica que
  exista (400 si no). fecha por defecto = CURRENT_DATE. numero_compra
  correlativo 000001, 000002... con la secuencia. Todo en una transaccion.
